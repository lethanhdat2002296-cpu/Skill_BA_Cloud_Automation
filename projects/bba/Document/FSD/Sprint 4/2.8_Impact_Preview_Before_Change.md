## 2. Purpose and background

Before changing a setting, the user sees which centres are affected and how — the old → new value for each centre, and the children affected — and only then confirms the change.

## 3. Scope and phase boundaries

| In scope | Out of scope |
|---|---|
| List of configuration settings and the value at each centre. Change a setting, see the impact (See the impact), confirm. Keep a history of changes. | The catalogue of settings for each module. Setting a centre-specific value. Approval of setting changes. |

## 4. Actors, roles and access

| Actor | Scope | Rights / Responsibilities |
|---|---|---|
| Authorised User | Settings and centres within the user's role and data scope. | View settings and the value at each centre; change settings at the levels the user is allowed to; see the impact and confirm; export. |
| System | Settings; children's data within scope. | Work out inherited values, work out the impact, record history. |
| Unauthorised User | Outside the role or data scope granted. | Does not see the Settings screen or restricted actions; cannot change data. |

**General rule:** Detailed rights for each role are configured by BBA in Roles & permissions. This FRS does not fix rights to any specific role.

## 6. Functional requirements by user story

### 6.1 BBA-51: US-001 - Change a setting with an impact preview

#### User Story

As a user, I want to see which centres are affected, and how, before I save a change.

#### Functional Requirements

| FR ID | Functional requirement |
|---|---|
| FR-001 | A user with the right can change the value of a setting. |
| FR-002 | The impact of the change on centres is shown before saving (BR-001). |
| FR-003 | The change is saved when the user confirms (BR-002). |

#### Functional Flow - Main

1. The user selects Change, chooses the scope of the change — for example Brand, Centre or Country — and enters the new value (FR-001).
2. The user selects See the impact; the system checks the value and shows the impact on centres or children (FR-002; VAL-001).
3. The user selects Confirm; the system saves the change, updates the Set by column and records history for each centre (FR-003; AUDIT-001).

#### Functional Flow - Alternative

1. The user closes the dialog (Close) at the impact step: nothing changes.
2. The user changes the scope or the value after seeing the impact: the previous impact is cleared and the user must select See the impact again (BR-001).
3. The user selects View list in the impact panel: the children using the value are shown, by centre (FR-002; BR-001).

#### Functional Flow - Exception

1. Invalid value: no impact is shown and nothing is saved (VAL-001).

#### Business Rules

| BR ID | Rule |
|---|---|
| BR-001 | On See the impact, the system shows: (1) the centres whose value will change; (2) the number of children and the number of centres using the value being changed, with a View list link to see those children by centre. Confirm is available only after the impact has been viewed; changing the scope or the value requires viewing the impact again. |
| BR-002 | On each Confirm, the system records history for each centre changed: who changed it, when, and from which value to which value. |

#### Validation Rules

| VAL ID | Condition | System response |
|---|---|---|
| VAL-001 | The value is of the wrong type or outside the range allowed for the setting. | No impact is shown and nothing is saved; an error is shown at the value field. |

## 7. Appendix

### Appendix A. Glossary

| Term | Meaning in this FRD |
|---|---|
| Impact preview | The centres whose value changes (old → new) and the number of children using the value being changed, shown on See the impact, before Confirm. |
| Discontinued | The state of a value removed from a list-type setting: it cannot be chosen for new records; records already using it keep it. |
