## 2. Purpose and background

Before changing a setting (for example the invoice due day or the notice period), the user sees the current value at each centre and what the change will affect — which centres get a new value and how many children, invoices and waiting requests are touched — and only then confirms.

## 3. Scope

| In scope | Out of scope |
|---|---|
| List of settings by group, value and source at each centre, "Set at", "Mark as confirmed by BBA". Changing a setting by level (Applies to), checking the value, See the impact, Confirm. Centre overrides and removing them. Feature switches by brand and centre, blocked while related work is still open. Change history. | The list of settings of each module. Shared lists. Approval of setting changes. |

## 4. Users, roles and access

| User | Scope | Rights / Responsibilities |
|---|---|---|
| HQ Admin (BBA IT) | Every country, brand and centre. | Full rights; manages approval routes and settings; can give extra permissions to staff of any centre; can decide an approval step on behalf of the role that owns it. |
| HQ Ops / Head of Brand, District Manager, Operations Manager | Brand, cluster and the centres they look after. | Changes the settings they are allowed to change; approves requests in approval routes. |
| Centre Director | Own centre. | Gives extra permissions to staff of the centre; changes centre-level settings they are allowed to change; approves the centre's requests. |
| System | Whole system. | Sends requests to approvers by route, works out impact, ends permissions on their end date, keeps history, sends notifications. |

**General rules:** only users with Administration rights can open the Administration screens; actions a user may not take are not shown; history can only be added to, never edited or deleted; standard lists offer search, filters, sorting, 20 / 50 / 100 rows per page and export of the filtered list.

## 6. Requirements by user story

### 6.1 BBA-51: US-001 - Impact preview before a setting change

#### User Story

As an HQ Admin, I want to see each centre's current value and the effect of a change before I save it, so that I do not change by mistake a setting that affects many children, invoices and requests.

#### Functional Requirements

| FR ID | Requirement |
|---|---|
| FR-001 | Settings are grouped into Fees, Joining & leaving, Daily operations, Learning and Communication; search by setting name. |
| FR-002 | A setting shows its name, unit, "Set at" (the levels where it can be set and the default value, for example "Set at: Group · default 5") and the "Value at every centre" table: Centre, Value, Comes from (Default, Group, Country, Brand, Cluster, Centre), Set by (person and time), Override; centres can be filtered by country, brand, "Differs from default" and "Not yet confirmed". |
| FR-003 | A user with the right to do so chooses Change, picks "Applies to" from the levels allowed by "Set at" (Group, Country, Brand, Cluster or Centre) and enters the new value; the system checks the value. |
| FR-004 | Choosing "See the impact" before Confirm shows the number of centres affected and the list "Centre: old value → new value" (first 8 rows, then "and n more"), together with the number of children, invoices and waiting requests affected. |
| FR-005 | On Confirm, centres without their own override take the new value; centres with an override keep theirs. |
| FR-006 | An override sets a centre's own value in place of the inherited one; removing the override returns the centre to the inherited value. |
| FR-007 | A setting whose default has not been confirmed shows "⚠" in the list and "⚠ To confirm with BBA" in the detail, with the action "Mark as confirmed by BBA". |
| FR-008 | Turning off a feature switch is blocked while related work is still open; the system shows a link to that work. |
| FR-009 | Every change is recorded in history: setting, old value, new value, who changed it and when; settings by centre can be exported. |
| FR-010 | Feature switches tab: each feature has the note "Off hides: …" and an on/off switch for the brand ("Whole brand", "x of y on") and for each centre; turning off still goes through the check in FR-008. |

#### Functional Flow - Main

1. The user opens a setting; the system shows the value and source at each centre (FR-002).
2. The user chooses Change, picks Applies to and enters the new value (FR-003).
3. The user chooses See the impact; the system checks the value (VAL-001) and shows the impact (FR-004).
4. The user chooses Confirm; the system saves, centres without an override take the new value, the Comes from and Set by columns update, and history is recorded (FR-005, FR-009).

#### Functional Flow - Alternative

1. The user cancels at the impact step: nothing changes.
2. Set or remove an override for one centre (FR-006).
3. Choose "Mark as confirmed by BBA" for a setting marked ⚠ (FR-007).
4. Turn a feature on or off for a whole brand or one centre in the Feature switches tab (FR-010).

#### Functional Flow - Exception

1. Invalid value: the impact is not shown and nothing is saved (VAL-001).
2. Turning off a feature with open work: blocked, with a link to the work (FR-008; VAL-002).

#### Business Rules

| BR ID | Rule |
|---|---|
| BR-001 | Settings pass down from country → brand → cluster → centre; a lower level can override; removing an override brings back the inherited value. |
| BR-002 | Every setting change is checked, shows its impact before saving and is recorded in history. |
| BR-003 | Turning off a feature is blocked while related work is still open. |

#### Validation Rules

| VAL ID | Condition | System response |
|---|---|---|
| VAL-001 | The value is the wrong type or outside the range allowed for the setting. | The impact is not shown and nothing is saved; an error shows at the value field. |
| VAL-002 | Turning off a feature while work is still open (for example photos waiting for review, children on the school bus). | Blocked; shows how many items are open and a link to them. |

## 7. Appendix

### Appendix A. Glossary

| Term | Meaning in this FRD |
|---|---|
| Impact preview | The number of centres whose value changes (old → new) and the number of children, invoices and waiting requests affected, shown on See the impact before Confirm. |
| Override | A lower level's own value used in place of the inherited value. |
| To confirm with BBA | ⚠ mark on a route or setting whose default value BBA has not yet confirmed. |
