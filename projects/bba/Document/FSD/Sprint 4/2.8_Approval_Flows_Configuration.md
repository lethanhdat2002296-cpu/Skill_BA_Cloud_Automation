## 2. Purpose and background

HQ Admin loads the default approval routes for every BBA request type (withdrawal, transfer, refund, leave, photos, discount…), adds separate routes for a country or brand, and changes the approver at each level and the amount threshold, so that approvals follow the way BBA works.

## 3. Scope

| In scope | Out of scope |
|---|---|
| Load default routes for every request type (Appendix A). Add route and Edit route: request type, country, brand, level 1 approver, level 2 approver (or one level only), amount threshold. Check for duplicate combinations. Effect on new requests. History of route changes. | Viewing, filtering and exporting the approval matrix (FRD 2.8 CRM Administration — BBA-49). Sending and approving requests (FRD 2.8 Change Request with Second Approval). The list of roles (Roles). |

## 4. Users, roles and access

| User | Scope | Rights / Responsibilities |
|---|---|---|
| HQ Admin (BBA IT) | Every country, brand and centre. | Full rights; manages approval routes and settings; can give extra permissions to staff of any centre; can decide an approval step on behalf of the role that owns it. |
| HQ Finance | Country / legal entity. | Reads routes and the change log; approves the finance routes (credit note, refund, notice waiver, discount level 2). |
| HQ Ops / Head of Brand, District Manager, Operations Manager | Brand, cluster and the centres they look after. | Changes the settings they are allowed to change; approves requests in approval routes. |
| System | Whole system. | Sends requests to approvers by route, keeps history, sends notifications. |

**General rules:** only users with Administration rights can open the Administration screens; actions a user may not take are not shown; history can only be added to, never edited or deleted; standard lists offer search, filters, sorting, 20 / 50 / 100 rows per page and export of the filtered list.

## 6. Requirements by user story

### 6.1 BBA-53: US-001 - BBA approval flows configuration

#### User Story

As an HQ Admin, I want to load the default routes for every request type (withdrawal, transfer, refund, leave, photos, discount…), add separate routes by country and brand, and change the approver at each level, so that approvals follow the way BBA works.

#### Functional Requirements

| FR ID | Requirement |
|---|---|
| FR-001 | Load default routes creates a route for every request type from the default list in Appendix A; HQ Admin can edit them afterwards. |
| FR-002 | The Add / Edit route window has Request type, Country (All / Singapore / Malaysia), Brand (All brands or one brand), Level 1 approver, Level 2 approver ("None — one level" or a role) and "Level 2 only above this amount". The amount field only appears once a level 2 role is chosen; leaving it empty means both levels always apply ("Always both levels"). Roles available: Centre Director, District Manager, Operations Manager, Head of Brand, Finance, HQ Admin. |
| FR-003 | Requests submitted after saving follow the new route; requests already waiting keep the approvers they were sent to. |
| FR-004 | Each time a route is added or edited, History records a line: time, person, request type, old level 1 → level 2 and new level 1 → level 2. |
| FR-005 | Add route creates a route for a combination of Request type + Country + Brand that has no route yet, for example a separate route for one brand. |

#### Functional Flow - Main

1. HQ Admin opens Approval routes; if there are no routes yet, HQ Admin chooses Load default routes (FR-001).
2. HQ Admin chooses Edit on a route, or Add route (FR-002, FR-005).
3. HQ Admin picks the level 1 role, the level 2 role (or "None — one level") and enters a threshold if needed (FR-002; VAL-001, VAL-002, VAL-003).
4. HQ Admin chooses Save route; the system records History; new requests follow the new route (FR-003, FR-004).

#### Functional Flow - Alternative

1. Choosing "None — one level" for level 2: the amount field is hidden and the threshold is cleared; the route has level 1 only (FR-002).

#### Functional Flow - Exception

1. No level 1 role: not saved (VAL-001).
2. The threshold is not a positive number: not saved (VAL-002).
3. Add route with a combination that already exists: not saved (VAL-003).

#### Business Rules

| BR ID | Rule |
|---|---|
| BR-001 | A route has at most 2 levels and an optional amount threshold. |
| BR-002 | Default routes can be edited. |

#### Validation Rules

| VAL ID | Condition | System response |
|---|---|---|
| VAL-001 | No level 1 approver role. | Not saved; the field is marked as required. |
| VAL-002 | The threshold is not a positive number. (The field is not shown until a level 2 role is chosen.) | Not saved; shows "Enter an amount above 0, or leave it empty to always use both levels." |
| VAL-003 | Add route with a Request type + Country + Brand combination that already has a route. | Not saved; shows "A route for this request type, country and brand already exists. Edit that route instead." |

| To confirm with BBA | ⚠ mark on a route or setting whose default value BBA has not yet confirmed. |
