# 2. Purpose and Background

This FRS specifies how an authorised CRM user Inactive an eligible Lead and all linked Enquiries, and how the retained Inactive Lead can be found and viewed. The feature preserves the Lead, its related records and audit history; it does not delete records or merge one Lead into another.

Inactive Lead is a user-initiated lifecycle action in the CRM interface. It is separate from Lead duplicate detection.

# 3. Scope and Phase Boundaries

| In Scope                                                                                                                                                                                                             | Out of Scope                                                                                                                                                                                                       |
|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Inactive Lead action; linked-Enquiry preview; atomic inactivation of the Lead and linked Enquiries; read-only Inactive Lead access; role-based access; status search; audit; reporting boundary; and error handling. | Restoration of prior statuses; Lead merge; physical deletion; data copying, movement or relinking; reassignment of related records; new API or integration events; notification, approval or escalation workflows. |

Boundary: This feature changes lifecycle statuses only. It does not create, move or relink Lead, Contact, Enquiry, Relationship, Visit, Call, Invoice or Reference Log data.

# 4. Actors, Roles and Access

| Actor             | Scope                                                                | Permission / Responsibility                                                                                                  |
|-------------------|----------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------|
| Authorised User   | Lead records available under the existing role and data-scope model. | May use Inactive Lead when the role grants the action and the Lead is eligible.                                              |
| Lead Viewer       | Lead records available under the existing role and data-scope model. | May view Inactive Leads when the user can view the Lead list; view permission is not restricted by Lead status.              |
| System            | Target Lead and all linked Enquiries.                                | Revalidates access and current state, applies the atomic transaction, records audit history and returns the standard result. |
| Unauthorised User | Outside the permitted role or data scope.                            | Must not see or execute restricted actions and must not change Lead or Enquiry data.                                         |

All action and view access follows the existing role-based permission model. This feature introduces no separate reviewer role and no status-specific view restriction.

# 6. Functional Requirements by User Story

## 6.1 BBA-40: US-001 - Inactivate Lead and Linked Enquiries

### User Story

As an authorised user, I want to inactive a Lead and its linked Enquiries so that the Lead and related active Enquiries leave active processing while all records and history remain retained.

### Functional Requirements

| **FR ID** | **Functional Requirement**                                                                                                            |
|-----------|---------------------------------------------------------------------------------------------------------------------------------------|
| FR-001    | Provide Inactive Lead on the Lead Detail page and in the Lead list action menu when the Lead is eligible under BR-002 and VR-001/002. |
| FR-002    | Before any status change, retrieve all linked Enquiries and present their count and current details in a confirmation view.           |
| FR-003    | Allow the user to open a linked Enquiry Detail page in a separate tab from the confirmation view.                                     |
| FR-004    | Provide Cancel and Inactive Lead and Enquiries as the confirmation choices; Cancel makes no changes.                                  |
| FR-005    | On confirmation, revalidate permissions and current record states, then apply the status transaction under BR-001/003/004/005.        |
| FR-006    | Record status-change audit entries under DATA-002/003 and present the standard success or failure result.                             |
| FR-007    | Do not require a reason, approval, notification or escalation for the Inactive Lead action.                                           |

### Functional Flow - Main

1.  The authorised user selects Inactive Lead from Lead Detail or the Lead list (FR-001).

2.  The system validates access and eligibility, retrieves linked Enquiries and displays the confirmation view (FR-002; VR-001/002).

3.  The user reviews the count and Enquiry details, then selects Inactive Lead and Enquiries (FR-004).

4.  The system revalidates and commits the status and audit changes atomically (FR-005/006; BR-001/003/004/005).

5.  The system displays the standard success result (FR-006).

### Functional Flow - Alternative

1.  Cancel: the user selects Cancel; the confirmation view inactive and no data changes (FR-004).

2.  No linked Enquiry: the system displays a count of zero; the user may still confirm inactivation

3.  of the Lead (FR-002/005).

4.  Already-Inacitve Enquiry: the system leaves that record unchanged and processes the other linked Enquiries (BR-005; DATA-003).

5.  Enquiry detail: the user opens an Enquiry Name link in a separate tab, then may return to the confirmation view (FR-003).

### Functional Flow - Exception

1.  Missing, inaccessible or already-Inactive Lead: the action is not available or is denied without changing data (VR-001/002).

2.  A concurrent Lead or Enquiry change is detected on revalidation: cancel the transaction and request refresh (VR-003).

3.  Any required Lead, Enquiry or audit update fails: roll back the whole transaction and show the standard failure result (VR-004; BR-004).

### Business Rules

| BR ID  | Rule                                                                                                                    |
|--------|-------------------------------------------------------------------------------------------------------------------------|
| BR-001 | Inactive Lead changes Lead Status to Inactive; it does not delete the Lead.                                             |
| BR-002 | Access follows the existing role-based permission model and configured data scope.                                      |
| BR-003 | The action inactive all linked Enquiries in the same transaction.                                                       |
| BR-004 | The transaction is atomic: either all required status changes and audit records succeed or all changes are rolled back. |
| BR-005 | An Enquiry that is already Inactive remains Inactive and receives no new status-change audit entry.                     |
| BR-006 | The feature does not copy, move, relink or merge data.                                                                  |

### Validation Rules

| VAL ID  | Condition                                                                   | System Response                                                                           |
|---------|-----------------------------------------------------------------------------|-------------------------------------------------------------------------------------------|
| VAL-001 | The user lacks permission or record scope.                                  | Do not execute the action or change data; apply the standard access-denied behaviour.     |
| VAL-002 | Lead Status is Inactive.                                                    | Do not display Inactive Lead.                                                             |
| VAL-003 | The Lead or a linked Enquiry changes after the confirmation view is loaded. | Cancel the transaction, show the standard failure result and require the user to refresh. |
| VAL-004 | Any required Lead, Enquiry or audit update fails.                           | Roll back the entire transaction and show the standard failure result.                    |

## 6.2 BBA-40: US-002 - Find and View a Inactive Lead

### User Story

As a user with Lead view permission, I want to find and inspect Inactive Leads so that retained records and audit history remain available within my normal data scope.

### Functional Requirements

| **FR ID** | **Functional Requirement**                                                                                                        |
|-----------|-----------------------------------------------------------------------------------------------------------------------------------|
| FR-008    | Return Leads of all statuses, including Inactive, within the user’s existing Lead view permission and data scope.                 |
| FR-009    | Support Lead Status search and user-defined filters that can include Inactive; no default Inactive-only filter is required.       |
| FR-010    | Allow a permitted user to open the retained Inactive Lead and its audit history for viewing.                                      |
| FR-011    | Present Inactive Lead information as view-only and make prohibited edit, create and association actions unavailable under BR-009. |

### Functional Flow - Main

1.  A user with Lead view permission opens the Lead list (FR-008).

2.  The system loads all permitted Leads without excluding Inactive status (BR-007; VR-005).

3.  The user searches by Lead Status and opens a Inactive Lead (FR-009/010).

4.  The system shows the retained record and audit history in view-only mode (FR-010/011; BR-009).

### Functional Flow - Alternative

1.  The user applies a user-defined filter that includes Inactive, then opens a result (FR-009/010).

2.  The user follows another permitted navigation path to a Inactive Lead; the same view-only rules apply (FR-010/011) .

### Functional Flow - Exception

1.  A Lead is outside the user’s view scope: do not display or open it (VR-005).

2.  A user attempts an edit, create or association operation on the Inactive Lead: block it without changing data (VR-006; BR-009).

### Business Rules

| BR ID  | Rule                                                                                                                                                                                           |
|--------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| BR-007 | View access is based on existing Lead permissions and is not restricted by Lead Status.                                                                                                        |
| BR-008 | Inactive Leads are excluded from active-Lead and current-pipeline counts.                                                                                                                      |
| BR-009 | A Inactive Lead is read-only. Editing the Lead and every action that creates an object for the Lead or creates, changes or adds an association between the Lead and any object are prohibited. |

### Validation Rules

| VAL ID  | Condition                                                                                                                                             | System Response                                                                                                      |
|---------|-------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------|
| VAL-005 | The user lacks view permission or data scope.                                                                                                         | Do not display the Lead outside the existing access model.                                                           |
| VAL-006 | The user attempts to edit a Inactive Lead, create an object for it, or create, change or add an association between the Inactive Lead and any object. | Do not perform the operation; keep all data unchanged and apply the standard unavailable or access-denied behaviour. |

## 8. Glossary

| Term               | Definition in This FRS                                                                                                        |
|--------------------|-------------------------------------------------------------------------------------------------------------------------------|
| Inactive Lead      | A user action that changes Lead Status to Inactive and inactive linked Enquiries in one atomic transaction.                   |
| Inactive           | A retained Lead with Lead Status Inactive. It is excluded from active processing and is view-only under existing permissions. |
| Linked Enquiry     | An Enquiry related to the target Lead when the lifecycle action is processed.                                                 |
| Atomic transaction | A transaction in which every required status and audit change succeeds together or every change is rolled back.               |
| Reference Log      | An intake or source-processing record; it is not created, moved or relinked by this feature.                                  |
