# 2. Purpose and Background

This FRS specifies how an authorised CRM user views the chronological history of Lead and Enquiry engagement and follow-up activity. The Timeline presents approved Activities from Enquiry intake, Call Logs, outgoing email, Visits, follow-up, invoices, status changes, waitlist, Conversion, Centre transfer, and the later Trial capability.

The Enquiry is the owning context for interaction and state-change history. A Lead Timeline groups Activities by currently linked Enquiry; each Activity retains its owning Enquiry. The feature is a read-only history surface and does not create, edit, delete, re-parent or merge underlying business records.

# 3. Scope

| In Scope                                                                                                                                                                                                                                                                                                          | Out of Scope                                                                                                                                                                                                                                                                                   |
|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| View Enquiry-owned Timeline entries; view a Lead-level aggregate Timeline from linked Enquiries; show chronological activity information, actor and time when available; include the approved event categories; handle empty, unavailable and partial-load states; apply existing role, Centre and object access. | Creating or editing Calls, Messages, Visits, Trials, Transfers, Conversions or other source records; defining each owning module’s transaction rules; Journey configuration; reporting formulas; notification delivery; new public APIs; a Child Timeline; technical audit-log administration. |

# 4. Actors, Roles and Access

| Actor               | Scope                                                                            | Permission / Responsibility                                                                                                    |
|---------------------|----------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| Authorised CRM User | Lead and Enquiry records within the existing role, Centre and object data scope. | May view permitted Timeline entries and permitted event details in the current context.                                        |
| System              | Target Enquiry or Lead and linked Enquiries.                                     | Validates access, resolves context, retrieves permitted Activities, preserves owning-Enquiry identity and presents the result. |
| Unauthorised User   | Outside the permitted record or object scope.                                    | Must not see restricted records, event content or source-record navigation.                                                    |

Access follows the existing role-based permission, Centre data-scope and object-permission model. This feature introduces no new business role and does not grant access to a source record merely because a Timeline entry exists.

# 6. Functional Requirements by User Story

## 6.1 BBA-44: US-001 - View an Enquiry Timeline

### User Story

As an authorised CRM user, I want to view the chronological Activity history of one Enquiry so that I can understand engagement, follow-up and lifecycle events in their operational sequence.

### Functional Requirements

### Functional Flow - Main

1\. The user opens Timeline for an Enquiry.

2\. The system validates record and Timeline access.

3\. The system queries Activities for the Enquiry.

4\. The system applies event-content permissions.

5\. The system orders permitted Activities by source-event creation time to the second, newest first.

6\. The page displays the Timeline or approved empty state.

### Functional Flow - Alternative

1\. The Enquiry has no Activities: show the approved empty state.

2\. A Trial event does not yet exist because Trial is not delivered: no Trial event is fabricated.

3\. Some event fields are unavailable: show only the approved available fields.

### Functional Flow - Exception

1\. The Enquiry is inaccessible: do not load Timeline data.

2\. The Timeline service fails: keep other permitted Enquiry Detail content and show the approved Timeline error state.

3\. A restricted event is returned: do not render its restricted content.

## 6.2 BBA-44: US-002 - View a Lead Aggregate Timeline

### User Story

As an authorised CRM user, I want a Lead Timeline grouped by linked Enquiry, with the Enquiry having the newest Activity first, so that I can review the family’s care history without losing each Activity’s owning Enquiry.

### Functional Requirements

| FR ID  | Functional Requirement                                                                                                                                                                     |
|--------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-014 | The Lead Timeline groups permitted Activities by all currently linked Enquiries, including Closed Enquiries, without creating a Lead-owned copy.                                           |
| FR-015 | Each aggregated Activity shall retain its owning Enquiry identifier and relationship to the Lead.                                                                                          |
| FR-016 | The system shall include Activities only from linked Enquiries and Activity content the user is permitted to view.                                                                         |
| FR-017 | Each Enquiry group is ordered by its latest source-event creation time, newest first. Activities remain within their owning Enquiry group; no single interleaved Lead-level list is shown. |
| FR-018 | Display the owning Enquiry name as a link to its detail page when the user has access. Do not offer a source-record link from Timeline.                                                    |
| FR-019 | A Closed Enquiry remains in the aggregate while linked to the Lead. Unlinking does not reassign historical Activities to another Enquiry; history retention follows current system policy. |
| FR-020 | Each group displays its Enquiry name as a link and permitted entries with time, Activity name, Content, performer and Centre. The catalogue and Content are in Section 7.1.                |
| FR-021 | The Lead view distinguishes empty, partial and failed results using standard system messages and loads the latest permitted data on page/tab load or refresh.                              |
| FR-023 | Apply the existing system loading, paging, refresh and performance standards to the Lead Timeline.                                                                                         |

### Functional Flow - Main

1\. The user opens Timeline for a Lead.

2\. The system validates Lead access.

3\. The system resolves all currently linked and permitted Enquiries, including Closed Enquiries.

4\. The system retrieves permitted Activities for those Enquiries.

5\. The system groups Activities by Enquiry, orders Enquiry groups by their latest source-event creation time and displays the linked Enquiry name and permitted entries.

### Functional Flow - Alternative

1\. The Lead has no linked Enquiry or no permitted Activity: show the approved empty state.

2\. The user can access only some linked Enquiries: show only the permitted subset without exposing excluded Enquiry details.

### Functional Flow - Exception

1\. A linked Enquiry cannot be resolved: do not reassign its Activities; show the approved partial/unavailable state.

2\. Aggregation fails: do not replace the result with Activities from another Lead.

### Business Rules

| BR ID  | Rule                                                                                                                                               |
|--------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| BR-007 | Lead Timeline groups Activities by currently linked Enquiry and does not create a second Lead-owned Activity record.                               |
| BR-008 | Each Activity in Lead Timeline retains its owning Enquiry.                                                                                         |
| BR-009 | Only Activities from Enquiries currently linked to the Lead, including Closed Enquiries, and permitted to the user are eligible for display.       |
| BR-011 | Lead Timeline does not grant access to an Enquiry or source record outside the user’s existing permission and data scope.                          |
| BR-016 | Successful empty, partial-load and failed-load results are distinct display states.                                                                |
| BR-017 | Lead Timeline groups eligible Activities by owning Enquiry and orders groups by the latest source-event creation time in each group, newest first. |
| BR-019 | Lead group entries display only supplied and permitted Activity values; the view does not fabricate event facts or outcomes.                       |

### Validation Rules

| VAL ID  | Condition                                                      | System Response                                                                    |
|---------|----------------------------------------------------------------|------------------------------------------------------------------------------------|
| VAL-005 | The Lead is missing or inaccessible.                           | Do not display aggregate Timeline data; apply the standard result.                 |
| VAL-006 | A linked Enquiry is outside the user’s data scope.             | Do not expose that Enquiry or its restricted Activities in the aggregate view.     |
| VAL-007 | An Activity has no resolvable owning Enquiry.                  | Do not assign it to another Enquiry; apply the approved data-quality handling.     |
| VAL-011 | One source fails during Lead aggregation while others succeed. | Apply the approved partial-result rule and do not present the history as complete. |

# 7. Appendix and Glossary

## 7.1 Activity Catalogue and Content

The catalogue defines Timeline Activity types and content. Email records the sent event only. Display only source-supplied information permitted to the user.

| Module                  | When logged                                                              | Activity type                    | Content                                                                                            |
|-------------------------|--------------------------------------------------------------------------|----------------------------------|----------------------------------------------------------------------------------------------------|
| Enquiry                 | Enquiry created                                                          | Enquiry intake                   | Enquiry created + recorded source, channel or Reference Log where available.                       |
| Call                    | Call recorded (click to call or log call)                                | Call Log                         | Call outcome, brief note and next action date where captured.                                      |
| Email                   | Outgoing email sent                                                      | Outgoing email                   | Email subject and sent time. Delivery, receipt and read outcomes are not recorded in the Timeline. |
| Visit                   | Visit booked, rescheduled, cancelled, missed or completed                | Visit                            | Booking/ reschedule/ cancellation/ no-show or completion + date/time and outcome where captured.   |
| Follow-up               | Follow-up or next action recorded                                        | Follow-up / next action          | Activity kind, brief note and next action date where captured.                                     |
| Enquiry                 | Enquiry status changed                                                   | Enquiry status change            | Previous and new status + recorded reason or note where captured.                                  |
| Centre transfer         | Centre transfer recorded                                                 | Centre transfer                  | Previous and new Centre.                                                                           |
| Waitlist / conversion   | Waitlist or conversion outcome recorded                                  | Waitlist / Conversion            | Waitlist or conversion outcome.                                                                    |
| Trial                   | Trial registration, booking or completion recorded after module delivery | Trial                            | Registration/ booking or completion + date/time and outcome where captured.                        |
| Inactive Lead / Enquiry | Owning module records Lead or linked Enquiry closure                     | Inactive Lead / Inactive Enquiry | Inactive Lead or Enquiry and previous and new status.                                              |
| Invoice                 | Invoice created                                                          | Invoice created                  | Amount due and note, if recorded and permitted.                                                    |
| Invoice                 | Invoice paid                                                             | Paid invoice                     | Amount paid and note, if recorded and permitted.                                                   |

## 7.2 Glossary

| Term                    | Definition in This FRS                                                                                                                                                            |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Activity                | A business-facing history event produced by an approved owning module and associated with an Enquiry.                                                                             |
| Timeline                | The chronological CRM view of permitted Activities for one Enquiry or the aggregate view for one Lead.                                                                            |
| Owning Enquiry          | The Enquiry to which the Activity belongs under the approved data model.                                                                                                          |
| Lead aggregate Timeline | A Lead view that groups permitted Activities by their currently linked owning Enquiry, with the group containing the newest Activity first; no Activity is copied or re-parented. |
| Creation time           | The time when the source event was created, used to order Timeline entries and Lead groups.                                                                                       |
| Source record           | The Call, Message, Visit, Trial, Transfer, Conversion or other business record that produced or supports an Activity.                                                             |
| Owning module           | The feature that validates and persists the source transaction and supplies its Timeline event.                                                                                   |
| Partial result          | A Timeline result in which at least one permitted source failed while other permitted Activities were returned.                                                                   |
| Technical audit log     | System-level access or change evidence; it is distinct from the business-facing Timeline unless explicitly mapped.                                                                |
