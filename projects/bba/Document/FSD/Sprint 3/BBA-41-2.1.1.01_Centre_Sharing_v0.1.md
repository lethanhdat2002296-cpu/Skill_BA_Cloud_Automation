# 2. Purpose and Background

This FRS specifies how one Lead becomes visible to multiple Centres. When the sharing list is initialised, the Centre of the user who first creates the Lead is the first Centre in the list. A Centre recorded in a qualifying Reference Log is added to the same sharing list. An authorised user may add a Centre according to the existing role-based permission model and may remove it when no linked Enquiry uses that Centre.

Centre sharing expands the Centre data scope for the Lead. Users at Centres in the sharing list access the Lead under the same role-based permission mechanism. Available actions remain controlled by user roles, object permissions and Lead status.

# 3. Scope and Phase Boundaries

| In Scope                                                                                                                                                                                                                                      | Out of Scope                                                                                                                                       |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| Initialise the Lead sharing list with the creator Centre; add distinct Centres from qualifying Reference Logs; permit authorised manual additions and removals; apply shared-Centre access, UI display, audit, validation and error handling. | Lead merge and duplicate-detection logic; Enquiry creation and duplicate rules; definition of Enquiry reporting logic; new external API contracts. |

Boundary: Centre sharing adds or removes a Centre relationship for a Lead. It does not create or modify an Enquiry, Contact or Reference Log.

# 4. Actors, Roles and Access

| Actor              | Scope                                                                        | Permission / Responsibility                                                                                                                                     |
|--------------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Authorised User    | Lead records available under the existing role, Centre and data-scope model. | May add a Centre when the role grants that action and may remove it when no linked Enquiry uses that Centre.                                                    |
| Shared-Centre User | Lead records shared with the user Centre and otherwise permitted by role.    | Accesses the Lead through the existing role-based permission mechanism. View, edit and related-object actions remain controlled by role and object permissions. |
| System             | Lead, creator Centre, Reference Log Centre and the Centre-sharing list.      | Initialises the list, adds qualifying Reference Log Centres, validates changes and applies current access controls.                                             |
| Unauthorised User  | Outside the permitted role or effective Centre scope.                        | Must not add or remove Centres or obtain access by bypassing the approved permission model.                                                                     |

# 6. Functional Requirements by User Story

## 6.1 BBA-41: US-001 - Initialise and Automatically Extend Centre Sharing

### User Story

As a Centre team user, I want the Lead sharing list to begin with the Centre of the user who first created the Lead and include qualifying Reference Log Centres so that authorised Centre teams can work with the same Lead without creating another Lead record.

### Functional Requirements

| FR ID  | Functional Requirement                                                                                                                                                                                   |
|--------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-001 | When a Lead is first created, initialise its sharing list with the Centre of the user who first created the Lead as the first Centre.                                                                    |
| FR-002 | After a qualifying Reference Log has been saved for an existing Lead, resolve its Centre against Centre master data and add that Centre if it is not already in the sharing list.                        |
| FR-003 | Keep one effective entry per Centre, even if multiple Reference Logs contain the same Centre.                                                                                                            |
| FR-004 | Display the names of the shared Centres in the Lead detail screen.                                                                                                                                       |
| FR-005 | Permit users at shared Centres to access the Lead under the existing role-based, Centre-scope and object-permission model.                                                                               |
| FR-006 | If automatic sharing fails after the Reference Log is saved, keep that Reference Log, notify the user that the Lead has not been shared, and show the error on the corresponding Reference Log entry.    |
| FR-007 | Do not create another Lead, Enquiry or Reference Log, merge Leads, or change Lead identity or linked Enquiries solely because of automatic Centre sharing.                                               |
| FR-008 | For pipeline, conversion, Lead-source and operational reporting, use Enquiry data and attribute each Enquiry to the Centre stored on that Enquiry; do not derive attribution from the Lead sharing list. |

### Functional Flow - Main

1.  The Lead creation process saves the Lead and identifies the creator user Centre (FR-001).

2.  The system initialises the sharing list with that Centre first (FR-001; BR-001).

3.  The upstream intake process successfully saves a qualifying Reference Log for the Lead (FR-002).

4.  The system resolves the Reference Log Centre against Centre master data and checks the current sharing list (FR-002; VAL-001/002).

5.  The system adds a distinct Centre, applies existing access controls and displays the shared Centre names on Lead detail (FR-002/003/004/005).

### Functional Flow - Alternative

1.  The Reference Log Centre is already shared: keep one Centre entry and do not add another (FR-003; VAL-002).

2.  Several Reference Logs identify the same Centre: display it once (FR-003; VAL-003).

3.  An authorised user later removes an automatically added Centre: apply the removal rules in US-002; do not change the Reference Log or prior history.

### Functional Flow - Exception

1.  The Reference Log has no Centre value or its value does not resolve to Centre master data: do not add a Centre; keep the saved Reference Log and apply its existing validation or error behaviour (VAL-001).

2.  Automatic sharing fails after Reference Log persistence: keep the Reference Log, notify the user and show the share error on its row (FR-006; VAL-004).

3.  If the Lead is Closed, sharing does not make prohibited edit, create or association actions available (BR-006).

### Business Rules

| BR ID  | Rule                                                                                                                                                                                                 |
|--------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| BR-001 | The Centre of the user who first created the Lead is the first Centre when the sharing list is initialised.                                                                                          |
| BR-002 | A Centre from a qualifying saved Lead Reference Log is effective only when its value resolves to a Centre record in Centre master data; each Centre appears once.                                    |
| BR-003 | Centre sharing expands Lead data scope but does not override role, object or Lead-status permissions. A different country, brand or operating organisation is not an additional sharing restriction. |
| BR-004 | Automatic sharing does not create another Lead, Enquiry or Reference Log, merge Leads, or change the Centre of a linked Enquiry.                                                                     |
| BR-005 | Reporting attribution uses each Enquiry and its own Centre, not the Lead Centre-sharing list.                                                                                                        |
| BR-006 | Centre sharing does not override the Closed Lead restrictions defined in the Inactive Lead FRS.                                                                                                      |

### Validation Rules

| VAL ID  | Condition                                                                                    | System Response                                                                                                                   |
|---------|----------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| VAL-001 | The Reference Log has no Centre value or the value cannot be resolved to Centre master data. | Do not add a Centre; retain the saved Reference Log and apply its existing validation or error behaviour.                         |
| VAL-002 | The Reference Log Centre already exists in the sharing list.                                 | Keep the current list; do not create a duplicate Centre entry.                                                                    |
| VAL-003 | Several Reference Logs identify the same Centre.                                             | Keep and display one effective Centre entry.                                                                                      |
| VAL-004 | Automatic sharing fails after the Reference Log is saved.                                    | Keep the Reference Log; notify the user and show an error on its entry stating that the Lead has not been shared with the Centre. |

## 6.2 BBA-41: US-002 - Manually Manage Shared Centres

### User Story

As an authorised user, I want to add or remove Centres in the Lead sharing list so that Centre access reflects the current operational need and my role permissions.

### Functional Requirements

| FR ID  | Functional Requirement                                                                                                                                                                                                                          |
|--------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-009 | An authorised user may add one or more active eligible Centres to an editable Lead, including Centres in other countries, brands or operating organisations, subject to existing permissions.                                                   |
| FR-010 | An authorised user may remove any shared Centre, including one added from a Reference Log, only when no linked Enquiry uses that Centre. Remove sharing-based access without changing prior history or any Reference Log.                       |
| FR-011 | When several Centre changes are submitted together, save each valid change independently; retain successful changes and identify each failed Centre.                                                                                            |
| FR-012 | For each successful user-initiated add or removal, audit the actor, timestamp and Centre list before and after the change. Continue to audit permitted Lead and related-object changes made by shared-Centre users under the current mechanism. |
| FR-013 | Manual Centre sharing does not create a Lead, Enquiry or Reference Log and does not change the Centre on any linked Enquiry.                                                                                                                    |
| FR-014 | Use standard CRM success and failure messages. No approval, business notification or escalation is required for manual add or removal.                                                                                                          |
| FR-015 | Revalidate role permission, Lead status and current sharing data immediately before Save; reject a conflicting concurrent save and require review of refreshed data.                                                                            |

### Functional Flow - Main

1.  An authorised user opens an editable Lead and starts Centre sharing (FR-009; VAL-005/006).

2.  The system shows the current sharing list and eligible active Centres (FR-009).

3.  The user selects Centres to add or remove and chooses Save (FR-009/010).

4.  The system revalidates permission, Lead status, Centre eligibility, duplicate entries, linked-Enquiry use and current sharing data (FR-015; VAL-007/008/011/012).

5.  The system saves each valid Centre change, updates effective access and audits successful user-initiated changes (FR-010/011/012).

6.  The system displays the standard result, identifying every failed Centre if the save was partial (FR-011/014).

### Functional Flow - Alternative

1.  Cancel: close the editor without changing Centre-sharing data.

2.  An add selection is already shared: do not add a duplicate and inform the user (VAL-007).

3.  No eligible Centre is available: show no additional selectable Centre.

4.  No addition or removal is selected: Save leaves Centre-sharing data unchanged (VAL-009).

### Functional Flow - Exception

1.  The Lead is missing, inaccessible or Closed, or the user lacks permission: deny the change without modifying data (VAL-005/006).

2.  A selected Centre becomes invalid: reject that Centre, preserve other successful changes and identify the failed Centre (VAL-010).

3.  A linked Enquiry uses a Centre selected for removal: keep that Centre shared and tell the user why removal is blocked (VAL-011).

4.  A persistence failure occurs for one change: do not show it as saved; preserve successful changes and identify each failure (VAL-013).

5.  A concurrent change conflicts with the selected list: reject the conflicting save, refresh sharing data and require user review before saving again (VAL-012).

### Business Rules

| BR ID  | Rule                                                                                                                                                                             |
|--------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| BR-007 | Manual add and removal require existing role and object permissions. An active Centre in another country, brand or operating organisation is not excluded solely on that basis.  |
| BR-008 | A Centre already present in the sharing list is not added again.                                                                                                                 |
| BR-009 | A Centre may be removed, regardless of how it was added, only when no linked Enquiry uses it. Removal ends sharing-based access but retains any Reference Log and prior history. |
| BR-010 | Manual sharing does not create a Reference Log, another Lead or an Enquiry, and does not change the Centre of a linked Enquiry.                                                  |
| BR-011 | The Closed Lead restrictions in the Inactive Lead FRS override manual Centre-sharing actions.                                                                                    |
| BR-012 | Successful user-initiated sharing-list changes and permitted changes by shared-Centre users follow the existing audit mechanism.                                                 |
| BR-013 | In a multi-Centre submission, successful changes remain saved even if another Centre change fails.                                                                               |
| BR-014 | Manual sharing needs no approval, business notification or escalation; the acting user receives the standard operation result.                                                   |

### Validation Rules

| VAL ID  | Condition                                                                        | System Response                                                                                                 |
|---------|----------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| VAL-005 | The user lacks the required permission or the Lead is missing or inaccessible.   | Do not expose or execute the change; keep data unchanged and apply standard access-denied or failure behaviour. |
| VAL-006 | The Lead is Closed.                                                              | Do not make manual Centre sharing available.                                                                    |
| VAL-007 | A selected Centre is already in the sharing list.                                | Do not add a duplicate and state that the Centre is already shared.                                             |
| VAL-008 | A selected active Centre is in another country, brand or operating organisation. | Apply the existing user permission model only; allow selection when permitted.                                  |
| VAL-009 | The user makes no addition or removal.                                           | Save without changing Centre-sharing data.                                                                      |
| VAL-010 | One Centre is invalid in a multi-Centre submission.                              | Reject that Centre, keep successful changes and identify the failed Centre.                                     |
| VAL-011 | A linked Enquiry uses a Centre selected for removal.                             | Keep that Centre in the list and inform the user why removal is blocked.                                        |
| VAL-012 | A concurrent change conflicts with the current sharing list.                     | Reject the conflicting save, refresh sharing data and require user review.                                      |
| VAL-013 | Persistence fails for one or more Centre changes.                                | Do not show failed changes as saved; keep successful changes and identify each failed Centre.                   |

# 7. Glossary

| Term                   | Definition in This FRS                                                                                                                                                                       |
|------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Lead Creator Centre    | The Centre of the user who first created the Lead. It is the first Centre when the sharing list is initialised.                                                                              |
| Shared Centre          | A Centre in the Lead sharing list whose users may access the Lead under approved role and data-scope rules.                                                                                  |
| Automatic Centre Share | A Centre added to the sharing list from a Reference Log when its value resolves to a Centre record in Centre master data.                                                                    |
| Manual Centre Share    | A Centre added directly by an authorised user.                                                                                                                                               |
| Reference Log          | A Lead intake record created when a duplicate Lead is identified. If it contains a Centre and that Centre is not already in the Lead sharing list, the system adds the Centre automatically. |
| Lead Sharing List      | The distinct list of Centres that can access the Lead under current role permissions.                                                                                                        |
