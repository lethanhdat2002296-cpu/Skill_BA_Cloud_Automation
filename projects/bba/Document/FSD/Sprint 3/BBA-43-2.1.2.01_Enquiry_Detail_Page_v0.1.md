# 2. Purpose and Background

This FRS specifies the full Enquiry Detail page used to review one Enquiry in its operational context. The page brings together Enquiry information, the assigned Customer Journey and Tasks, status-permitted Actions and SLA information, related operational tabs, and links to the related Lead and Child when those records exist.

The feature is a presentation and orchestration surface. It does not calculate Enquiry Score, create SLA clocks or redefine the business rules that create or update Visits, Calls, Messages or Invoices. Those behaviours remain owned by their respective requirements.

# 3. Scope and Phase Boundaries

| In Scope                                                                                                                                                                                                                                                                                                                                                                                                              | Out of Scope                                                                                                                                                                                                                                                                                                                                     |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Open one authorised Enquiry in a full page; display confirmed Enquiry information fields; show the assigned Journey Template States and Tasks; show status- and permission-allowed Actions; show task/action items due today; provide Timeline, Visits, Calls, Messages and Invoices tabs with search, filter, descending creation-time sort and refresh-on-load; and link the related Lead and Child when permitted. | Creating or editing Journey Templates; calculating Enquiry Score; configuring SLA thresholds or clocks; detailed creation/update rules for Visits, Calls, Messages or Invoices; Trials tab; reporting definitions; Lead/Enquiry duplicate processing; new public API contracts. No new KPI, pipeline, conversion or counting formula is defined. |

# 4. Actors, Roles and Access

| Actor                 | Scope                                                                      | Permission / Responsibility                                                                                                         |
|-----------------------|----------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| Authorised CRM User   | Enquiries available under the existing role, Centre and object data scope. | May open Enquiry Detail and see only fields, tabs and related records permitted by the current access model.                        |
| Journey Task Assignee | Tasks assigned through the Enquiry Journey runtime.                        | May complete an eligible Manual Task when both task-assignment and role permissions allow it.                                       |
| System                | Target Enquiry and related records.                                        | Loads page data, evaluates visibility, derives Journey runtime presentation, returns allowed Actions and refreshes affected panels. |
| Unauthorised User     | Outside the permitted role, Centre or object scope.                        | Must not view the Enquiry, restricted fields, Actions, tabs or related records.                                                     |

Access follows the existing role-based permission, Centre and object data-scope model. BBA-43 does not create a new role. Required fields and read-only fields are identified in the UI Components tables, and Manual Task, Action, tab and related-record access follows the user's current permissions.

## 6.1 BBA-43: US-001 - View Enquiry Information and Related Records

### User Story

As an authorised CRM user, I want to open one Enquiry and review its identifying and operational information so that I can understand the current context and navigate to the related Lead or Child.

2\. One or more optional attribution fields are blank: the page displays the approved empty state without blocking the remaining content.

### Functional Flow - Exception

1\. The Enquiry is deleted, unavailable or outside scope: the page does not disclose its data.

2\. A related-link target becomes unavailable: navigation is blocked and the Enquiry page remains open.

## 6.2 BBA-43: US-002 - Review Customer Journey and Tasks

### User Story

As an authorised CRM user, I want to review the Journey assigned to an Enquiry and its Task progress so that I can understand the current State and outstanding work.

### Functional Requirements

| FR ID  | Functional Requirement                                                                                                                                                                          |
|--------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-009 | The system shall display the Journey Template assigned to the Enquiry and render its configured States and Tasks. The page does not need to display the Journey Template code, name or version. |
| FR-010 | The system shall render the number of Journey States configured in the assigned Journey Template in sequence on one horizontal row and shall not wrap States into multiple rows.                |
| FR-011 | The system shall identify the current State derived by the Journey runtime.                                                                                                                     |
| FR-012 | Each State shall display its configured Tasks and each Task shall show its name, completion status, owner/assignee and due information when supplied by the runtime.                            |
| FR-013 | An eligible user may complete a Manual Task.                                                                                                                                                    |
| FR-014 | An Automatic Task shall be read-only and shall complete only when its configured event becomes true.                                                                                            |
| FR-015 | The system shall not record the same Task completion more than once when the same completion event is processed repeatedly.                                                                     |
| FR-016 | Changing Enquiry Status shall not silently replace the saved Journey definition or version.                                                                                                     |
| FR-017 | The page shall show a clear unassigned or unavailable state when no Journey runtime can be loaded.                                                                                              |

### Functional Flow - Main

1\. The system resolves the Enquiry Journey assignment and saved version.

2\. The system loads configured States and Task runtime.

3\. The system renders States in sequence and identifies the current State.

4\. The user reviews Task name, assignment, due and completion information.

5\. If permitted, the user completes a Manual Task.

6\. The Journey runtime validates and saves the completion.

7\. The page refreshes progress and current State.

### Functional Flow - Alternative

1\. No Journey is assigned: the page shows the approved unassigned state.

2\. The Journey contains no Tasks: the assigned Journey area and empty Task state remain visible.

3\. Additional States extend horizontally and can be reached by horizontal scrolling.

### Functional Flow - Exception

1\. Journey runtime data fails to load: the page identifies the unavailable area without replacing it with stale data.

2\. A Task becomes completed or reassigned before the user acts: the attempted completion is rejected or refreshed by the runtime.

### Business Rules

| BR ID  | Rule                                                                                                                   |
|--------|------------------------------------------------------------------------------------------------------------------------|
| BR-005 | Customer Journey belongs to Enquiry and does not redefine the Lead or Child record.                                    |
| BR-006 | The page renders the Journey Template assigned to the Enquiry; its code, name and version are not displayed.           |
| BR-007 | Enquiry Status and Journey State are separate concepts.                                                                |
| BR-008 | Manual Tasks and Automatic Tasks follow different completion mechanisms; an Automatic Task cannot be manually checked. |
| BR-009 | Repeated processing of one completion event shall not record the same Task completion more than once.                  |

### Validation Rules

| VAL ID  | Condition                                                                                                         | System Response                                                                      |
|---------|-------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| VAL-005 | No Journey is assigned or the assignment cannot be resolved.                                                      | Display the approved unassigned/unavailable state; do not fabricate States or Tasks. |
| VAL-006 | The user attempts to complete an Automatic Task.                                                                  | Do not change the Task; retain event-driven completion.                              |
| VAL-007 | The user attempts to complete a Manual Task that is not assigned to the user or is outside the user's permission. | Do not change the Task; apply the standard unavailable or access-denied behaviour.   |
| VAL-008 | The Journey runtime changes while the page is open.                                                               | Refresh the Journey data before applying a Manual Task completion.                   |

## 6.3 BBA-43: US-003 - Use Allowed Actions and SLA Information

### User Story

As an authorised CRM user, I want to see only the Actions available for the current Enquiry and the applicable SLA state so that I can take a valid next step.

### Functional Requirements

| FR ID  | Functional Requirement                                                                                                                                                           |
|--------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-018 | The system shall display only Actions that are allowed for the current Enquiry Status, user permission and applicable business constraints.                                      |
| FR-019 | Action visibility shall remain separate from Journey Task configuration; the absence of Journey Tasks shall not by itself remove an otherwise permitted Action.                  |
| FR-020 | The page shall not permit direct editing of Enquiry Status through the information panel.                                                                                        |
| FR-021 | In Phase 1, the Actions & SLA area displays only task or Action items due today when supplied by the applicable service; it does not calculate or show an SLA clock or duration. |
| FR-022 | Prototype sample SLA durations shall not be treated as global product defaults.                                                                                                  |
| FR-023 | Selecting an Action shall hand off to the owning Action flow. BBA-43 shall not duplicate that Action’s validation or transaction logic.                                          |
| FR-024 | After a successful Action, the system shall refresh affected information, Journey runtime, Action eligibility, SLA and related tabs.                                             |
| FR-025 | If no Action is allowed, the panel shall show an approved no-available-actions state and shall not expose restricted Actions.                                                    |

### Functional Flow - Main

1\. The user opens the Actions & SLA panel.

2\. The system evaluates current Status, permission and applicable Action rules.

3\. The system displays only allowed Actions and any task or Action items due today.

4\. The user selects an Action.

5\. The owning Action flow revalidates and processes the request.

6\. The Enquiry Detail page refreshes affected areas after the result.

### Functional Flow - Alternative

1\. No Actions are allowed: the panel shows an approved empty state.

2\. SLA information is unavailable: Actions may still be shown according to their own rules while the SLA area shows the approved unavailable state.

### Functional Flow - Exception

1\. The selected Action became invalid: the owning flow blocks the operation and returns its standard result.

2\. Action or SLA service fails: the page does not substitute stale or invented eligibility data.

3\. Persistence or audit failure in a launched Action follows the owning feature’s failure and rollback behaviour; this page refreshes only after a confirmed result.

### Business Rules

| BR ID  | Rule                                                                                                                       |
|--------|----------------------------------------------------------------------------------------------------------------------------|
| BR-010 | Enquiry Actions are determined by Enquiry Status, user permission and applicable business constraints.                     |
| BR-011 | Action visibility is independent from Journey Task configuration.                                                          |
| BR-012 | Enquiry Status is not edited directly from the information panel; it changes through an approved Action or owning process. |
| BR-013 | Sample SLA values in the prototype are not universal defaults.                                                             |

### Validation Rules

|---------|--------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------|

| VAL-010 | Action eligibility or Enquiry state changed after the page loaded.             | Revalidate in the owning Action flow; do not process a stale Action.                      |
| VAL-011 | SLA information is not available in the current release or cannot be resolved. | Show the approved unavailable/empty state; do not display a fabricated clock or duration. |

## 6.4 BBA-43: US-004 - Review Related Timeline and Operational Tabs

### User Story

As an authorised CRM user, I want to review Timeline, Visits, Calls, Messages and Invoices for the current Enquiry so that I can work from one Enquiry context.

### Functional Requirements

|--------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-026 | The page shall provide separate Timeline, Visits, Calls, Messages and Invoices tabs in the Enquiry context.                                                                                                                        |
| FR-027 | Each tab shall load only records owned by or linked to the current Enquiry according to the owning module’s rules.                                                                                                                 |
| FR-028 | The Timeline tab shall present Enquiry activity/history entries supplied by the Timeline service, including performer and timestamp when those values exist.                                                                       |
| FR-029 | The Visits tab shall support opening a linked Visit and shall expose Book Visit only when the user and Enquiry are eligible. Booking from Enquiry Detail shall preselect and lock the Enquiry context under the Visit requirement. |
| FR-030 | The Calls tab shall support opening Call details and shall expose Create Log Call only when permitted. Create Log Call shall not be treated as Click to call.                                                                      |
| FR-031 | The Messages tab shall display outgoing emails sent by the system with email subject, sent date, Centre, sending channel (Email) and email delivery status, subject to the user's permissions.                                     |
| FR-032 | The Invoices tab shall support opening Invoice details and shall expose Create only when permitted by the owning finance requirement.                                                                                              |
| FR-033 | Selecting a tab or opening a record shall not re-parent, copy or merge the related record.                                                                                                                                         |
| FR-034 | When the Enquiry Detail page is loaded, each related tab refreshes its list. After an owning module saves a change, the selected tab and affected Timeline/summary data shall refresh.                                             |

### Functional Flow - Main

1\. The user selects a related tab.

2\. The system validates tab/object permission.

3\. The system loads records for the current Enquiry.

4\. The page displays the records in descending creation-time order with search and filter controls, or displays the approved empty state.

5\. The user opens a permitted record or create action.

6\. The owning module processes the operation.

7\. The page refreshes the selected tab and affected context.

### Functional Flow - Alternative

1\. The tab has no records: the approved empty state is shown.

2\. The user switches tabs: the Enquiry summary and identity remain unchanged, and the selected list is refreshed when the detail page is loaded.

3\. A create control is not permitted: the user may still view records when view permission exists.

### Functional Flow - Exception

1\. A tab service fails: only the affected tab shows an error and retry/refresh behaviour under the approved design.

2\. A related record becomes unavailable: navigation is blocked and the tab refreshes.
